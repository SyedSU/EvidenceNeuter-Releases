## 2026-10-23 workflow hardening

The legacy Hub Genesis publication workflow is retired: it cannot read signing secrets, create releases, or overwrite the stable locator. Only the canonical protected metadata workflow remains a publication path, with offline signing performed separately.

Candidate review now preflights the existing distribution-candidate environment before selecting it; it must meet the same exact main-only/reviewer/no-self-approval/no-admin-bypass policy as distribution-release. The publication workflow rechecks release protection after approval. No environments or credentials are created by these changes.

For candidate and publication workflows, reviewed_commit must equal the immutable main workflow commit GITHUB_SHA. Checkout uses that workflow SHA with credentials persistence disabled; the inline guard runs before dependency installation or repository release tools. This intentionally rejects arbitrary older/feature refs; dispatch the workflow from the reviewed main commit that contains the exact metadata/tooling bundle. This does not relabel product build commits or source locks.

Configure explicit nonsecret CATALOG_SEQUENCE_FLOOR, HUB_SEQUENCE_FLOOR and GENESIS_SEQUENCE_FLOOR from independently maintained highest accepted sequence records. A new envelope must advance its own role strictly above its floor; existing referenced product envelopes may equal their retained role floors during catalog activation. Missing/malformed floors block publication. Update the retained records after successful immutable upload; do not lower them to recover from errors. Publication runs are serialized, and public bundle signatures/anonymous bytes/expiry/floors are rechecked immediately before upload.

Hub envelopes use HUB_MANIFEST_PUBLIC_KEY_PEM; Genesis envelopes use GENESIS_MANIFEST_PUBLIC_KEY_PEM; catalogs use DISTRIBUTION_PUBLIC_KEY_PEM. No role falls back to another role's key. Sharing a root still requires explicit separate role bindings. The write token is supplied only to the final immutable metadata upload step; no inline production signing or clobber is performed. These source changes do not constitute a successful protected-environment rehearsal or public release.
